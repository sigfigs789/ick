# word<TAB>base<TAB>yes|no<TAB>reason<TAB>confidence
#
# yes  = the word is a transparent derived form of the base, so its rarity score
#        is capped at the base's frequency. Only pairs adjudicated at HIGH
#        confidence are recorded as yes, and only high-confidence yes rows are
#        compiled into src/data/llm-base-forms.json.
#
# A yes requires all four of:
#   1. the affix has exactly one meaning and is fully productive,
#   2. the base's dominant corpus sense is the sense the derived word is built
#      on -- this is the bar "husbander" fails, since "husband"'s frequency is
#      the spouse noun, not the verb meaning "to conserve",
#   3. the derived meaning is exactly base + affix, with no drift, and
#   4. no other base could plausibly have produced the word.
#
# no reasons: sense-mismatch (2 above), wrong-base (a real derivation, of some
# other word), coincidence (unrelated roots), drifted (meaning has moved),
# technical (a specialist sense), opaque (archaic or jargon formation),
# unverified (not cleared to the bar above), unsure.
